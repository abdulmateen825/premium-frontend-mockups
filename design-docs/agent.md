# Frontend Development Rules

## Priority
Build visually distinctive, polished interfaces quickly. Prioritize visual quality and working functionality over unnecessary architectural complexity.

## Execution Rules
- Never spend excessive time planning a straightforward frontend task.
- Inspect only the files relevant to the requested feature.
- Do not explore the entire codebase unnecessarily.
- Do not rewrite working components without a clear reason.
- Do not install new dependencies unless necessary.
- Do not generate lengthy reports or explanations.
- Make implementation decisions independently.
- Start implementing after a brief assessment.

## Design Rules
- Establish one consistent design system.
- Use deliberate color palettes and typography.
- Avoid generic AI-generated SaaS aesthetics.
- No unnecessary gradients, glassmorphism, glowing borders or decorative blobs.
- Use purposeful animations only.
- Prioritize spacing, alignment, hierarchy and visual balance.
- Reuse existing components and design tokens.

## Time Management
- Target 10–20 minutes for a typical isolated UI task.
- If a task is large, split it into independently working components.
- Implement the highest-impact screen first.
- Avoid overengineering.
- Do not spend time perfecting insignificant details while core features remain incomplete.

## Verification
- Run the relevant build or type check.
- Check the main screen at desktop and mobile widths.
- Fix obvious visual and functional issues.
- Report changed files and remaining issues briefly.

## Important
When asked to build a page, implement the page rather than spending the entire task producing a design proposal. Only ask questions when essential information is missing.
